# Risks

Known risks and mitigations. Review at wrap-up when something changed.

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| API keys + proxy credentials persist in plaintext localStorage (webview) | high | high | Backlog: OS keyring/stronghold; README no longer overclaims "secure storage" (S9) |
| `proxy_request` remains a broad fetch primitive for the webview (any http/https URL) | medium | high | S1 scheme check + S6 strict CSP shrink the attack path; full allowlist deferred (breaks custom `openaiBaseUrl`/local LLMs) |
| ~~Selection capture silently dead on Wayland sessions~~ (resolved 2026-09-19) | — | — | Wayland reads the PRIMARY selection through the compositor's X11 bridge, and the hotkey is registered with GNOME; verified end to end on GNOME 46 |
| GNOME custom shortcut entry and the placement extension survive uninstalling the app | medium | low | The package removes the system copy of the extension; the dconf entry and any per-user copy stay. README carries the two cleanup commands |
| Placement extension can break at a GNOME major upgrade | medium | low | It uses only long-lived APIs (window-manager `map`, `global.get_pointer`, `move_frame`); without it the popup still opens, just not at the pointer. `shell-version` lists 45–49 and needs a check each GNOME release |
| Electron's second instance takes ~1.4s to forward `--quick-translate` (full Chromium start) | medium | low | Only affects the Electron backend under Wayland (Ubuntu 18.04–20.04, where Wayland is rare). Tauri's second instance is far cheaper; a FIFO trigger is the fallback if this ever matters |
| Simulated Ctrl+C destroys user clipboard; stale clipboard translated when nothing selected | medium | medium | Backlog C12 (save/restore design) |
| /tmp PNG TOCTOU + leak in screenshot/OCR path | low | medium | Backlog C13 (tempfile Builder suffix, cleanup on all paths) |
| ~~No single-instance guard while autostart is enabled~~ (resolved 2026-09-19) | — | — | tauri-plugin-single-instance and Electron's requestSingleInstanceLock; a second launch focuses the running app |
| Residual ms-scale cross-window settings write race after S3 sync | low | low | Accepted; event-driven rehydrate self-heals on next change |
| Electron `closeAllConnections()` aborts every in-flight default-session request, so a concurrent POST can fail once when GET transport healing fires | low | low | HTTP statuses no longer heal; transport-only healing keeps the 10s cooldown. Documented in DECISIONS 0011 |
| Both no-key Google web endpoints are unofficial and may throttle or change together | medium | medium | Structured Chrome endpoint is primary, GTX is one fallback; if both fail the UI names both results and recommends another configured engine. Official Cloud API remains an opt-in future feature |
| Electron HTTP cache from v1.2.1 and older may contain provider GET URLs with translated text or credentials | high until upgrade | high | v1.2.2 clears the disposable HTTP cache at startup; both backends mark provider traffic no-store and Google text moved to POST bodies |
| Development/build dependency tree has 11 npm advisories (1 low, 10 high), including Electron's installer dependency and Vite-era tooling | low for trusted local builds | medium | `npm audit --omit=dev` is clean. Keep dev server localhost-only, build trusted inputs, and triage safe tool upgrades separately; Electron 44 is a major compatibility decision, not part of the focused v1.2.2 patch |
| WebKitGTK renders text outside a card noticeably heavier than text inside one | certain, Tauri build only | low (cosmetic) | Diagnosed natively 2026-09-20. NOT a CSS bug: computed styles are identical and an identical-text width probe matches to 0.1px. WebKit uses subpixel antialiasing only over an opaque layer; `.card` is opaque `--card`, while everything outside it sits on the transparent Tauri window and falls back to grayscale AA, which reads heavier and darker. Proven by giving the element an opaque background - it then matches. Electron/Chromium renders both identically ((114,114,114) vs (112,112,112)), so only the Tauri build is affected. Changing font-weight, the tag or font-family does nothing. The one-line fix is `-webkit-font-smoothing: antialiased` on `html`, which makes all text uniformly grayscale - a typography decision for the designer, so deliberately not applied |
| Electron will not start on this dev host: `chrome-sandbox` is not root-owned setuid | n/a to the shipped app | low | Dev-environment only, pre-existing. `node_modules/electron/dist/chrome-sandbox` is `wsh:wsh 0755`, and Electron aborts rather than run unsandboxed. The backend was verified by running `npx electron . --ozone-platform=x11 --no-sandbox` once; the committed script is unchanged. Packaged builds ship their own correctly-owned sandbox |
| Both engines claim the outermost window pixels for their own resize hit test | certain | low | Measured 2026-09-20: in Electron the app's handler does not fire at 2px or 5px inset but does at 7px, so Chromium consumes about the outer 6px; tao has a comparable 5px band on the GtkWindow. The handles are 8px edges / 16px corners so a usable band survives behind that. Harmless in practice — whichever layer wins, the user gets a resize — but do not shrink the band without re-measuring |
| The quick pop-up cannot be driven by UI automation | certain | none (test-only) | It closes on window blur by design, so `xdotool windowactivate` and any screenshot that steals focus hide it before a drag can start. Its resize and size-persistence therefore need a human. The persistence *gate* was proven in the browser instead: an automatic resize is not recorded, a handle-initiated one is, and the flag resets |
| WebKitGTK delivers no `pointermove` for mouse input, and no motion at all once the pointer leaves the window | certain | medium | Measured 2026-09-20: a handle's `pointerdown` fires but `pointermove` never does, and a `window`-level `mousemove` drag stalls as soon as the pointer passes the edge. Any hand-rolled drag/resize in the Tauri build is therefore unreliable — hand grabs to the compositor instead. Electron is unaffected (pointer capture works in Chromium) |
| A compositor grab that never starts leaves the pop-up briefly undismissable | low | low | The suppression flag clears on the next focus-in and after 1s regardless, so the worst case is one second of ignoring click-away. Escape closes the pop-up unconditionally |
